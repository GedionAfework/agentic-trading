1. Design Objectives and Principles
 Deterministic-first trading logic: AI cannot directly override hard strategy/risk gates.
 Private-by-default inference: LLM/VLM and embedding services reside on private network.
 Evidence-preserving workflows: every material decision can be traced to inputs, rules and model/prompt
versions.
 Asynchronous where expensive: ingestion, embedding, screenshot analysis, backtests and scans use durable
jobs.
 Idempotent boundaries: webhooks, notifications and jobs use idempotency keys/outbox patterns.
 Replaceable models/providers: model serving and market providers are abstracted behind stable interfaces.
 No baseline live execution capability: a future execution service must be separately designed, permissioned
and deployed.

4.2 Structured Output Validation
Each AI agent returns a versioned JSON schema. Free-form text is generated only after structured fields validate.
Invalid JSON, missing required evidence, unknown enum values or schema mismatch triggers one constrained
repair attempt; repeated failure returns a controlled error and does not progress the trading state machine.

8. Strategy Evaluation Design
Rules are stored as a constrained DSL/configuration, not arbitrary executable code. The evaluator resolves
features by name, applies typed operators, and records tri-state TRUE/FALSE/UNKNOWN. Composite nodes
support AND/OR/NOT with explicit unknown propagation.
{
"rule_id": "r-bos-confirm",
"type": "comparison",
"feature": "structure.bullish_bos",
"operator": "eq",
"value": true,
"required": true,
"weight": 20,
"evidence": ["swing_high_id", "break_candle_id"]
}
Evaluation Stage Design
Eligibility Match instrument, asset class, timeframe, session and enabled
status.
Feature resolution Compute or fetch feature values only from candles at/before
evaluation timestamp.
Predicate evaluation Typed operator returns TRUE/FALSE/UNKNOWN and reason.
Composite evaluation Apply nested boolean logic and required/optional semantics.
Score Calculate weighted score only after mandatory constraints;
score cannot override a required failure.
Evidence Persist feature ids/values/candle references and engine version.
Candidate creation Create setup only if configured candidate threshold/state is
reached.
9. Risk Engine Design
 Inputs are normalized decimal values, never binary floating point for persisted money/price fields.
 R:R = absolute(target-entry) / absolute(entry-stop), adjusted for direction.
 All price precision and tick-size validation use instrument metadata.

11. Security Design
Threat Control
Credential theft Argon2id password hashing, MFA, short-lived access tokens,
refresh rotation, session revoke.
Public model exposure Inference bound to private interface/network; firewall;
backend-only authentication.
Prompt injection from documents Treat retrieved text as data; tool permissions hard-coded; never
execute instructions from source content.
Malicious file upload Allowlist types, size limits, parser isolation, malware scan
where available, object key randomization.
Telegram impersonation Explicit account linking, check Telegram user/chat id, revoke
link capability.
Secret leakage Environment/secret manager, log filters, no secrets in
prompts/mobile bundle/database plaintext.
SQL injection ORM/parameterized queries; no model-generated SQL against
production DB.
SSRF Market/document fetchers use allowlisted domains and egress
controls.
Excessive AI resource use Per-user budgets, request size limits, queue limits, token caps,
GPU concurrency controls.

15. Coding and Operational Conventions
 UTC timestamps in persistence; display timezone selected by user.
 UUIDv7/UUID primary keys where available for sortable IDs.
 Decimal/Numeric for prices and money; integers for counts; explicit enums constrained in DB/application.
 Every request/job gets correlation_id; every agent workflow gets run_id.
 Migrations and strategy engine versions are immutable artifacts in release pipeline.
 Container images pinned by digest in production where practical.

Appendix D - Prompt and Tool Security Policy
 System prompts define role, scope, output schema, uncertainty policy and forbidden actions. They are
immutable/versioned per deployment.
 User text and retrieved documents are untrusted content. Statements such as "ignore previous instructions"
inside them must not alter system policy.
 No model receives raw database credentials, exchange secret keys, refresh tokens, Telegram bot token or
infrastructure private keys.
 Tool invocations are authorized outside the model. Even if model requests a forbidden tool/action, backend
rejects it.
 No arbitrary shell, Python execution, SQL execution, filesystem path access or arbitrary URL fetch tool is
exposed to agents in production.
 All external fetch tools use allowlisted providers and bounded parameters.
 Agent output is parsed against JSON Schema/Pydantic before trading workflow progression.
 Model-generated calculations are informational until recomputed/validated by deterministic code.
